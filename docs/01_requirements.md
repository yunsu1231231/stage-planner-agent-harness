# 01. 요구사항 정의서 (초안)

> 상태: **초안** — 기획 검증(`03_planning_validation.md`) 결과에 따라 수정한다.

## 1. 도메인: 공연 관람 플래너

사용자가 날짜·시간·지역·예산·이후 일정을 말하면, 실제 공연 목록과 회차 시각·러닝타임·가격을 조회하여 조건에 맞는 공연과 주변 장소를 추천하고, 관람 계획을 저장·관리한다.

### 1.1 도메인 선택 조건 충족 근거

| 조건 | 근거 |
|---|---|
| 외부 API 3종 | ① KOPIS 공연목록 ② KOPIS 공연상세 ③ 카카오 로컬 (보조: KOPIS 공연시설상세 — 좌표) |
| 판단이 필요한 요청 | 회차 시작 + 러닝타임 → 종료 시각을 계산해 제약 시각과 비교, 가격을 예산과 비교 |
| 재계획의 의미 | 조건 미충족 시 다른 회차 → 다른 공연 → 인접 지역/장르 순으로 대안 탐색 |
| 저장할 결과물 | 관람 계획 (공연명, 공연장, 날짜, 시작·종료 시각, 가격, 주변 장소) |
| 위험 도메인 여부 | 아님 → 면책 문구 없음 |

### 1.2 외부 API 목록 (출처·이용조건은 검증 시 확정)

| API | 제공 정보 | 출처 | 호출 한도 / 약관 |
|---|---|---|---|
| KOPIS 공연목록 | 기간·지역·장르별 공연 ID, 공연명, 공연장, 기간 | 예술경영지원센터 KOPIS | TBD (검증 시 기록) |
| KOPIS 공연상세 | 러닝타임, 요일별 공연 시각, 가격, 관람연령, 공연장 ID | 〃 | TBD |
| KOPIS 공연시설상세 | 공연장 주소, 위도·경도 | 〃 | TBD |
| 카카오 로컬 | 좌표 주변 식당·카페·주차장 이름/주소/링크 | 카카오 | TBD |

## 2. 서비스 시나리오

### 2.1 요청 분류 (의도)
| 의도 | 설명 | Tool 사용 |
|---|---|---|
| `plan_performance` | 조건에 맞는 공연 추천 | O |
| `fact_query` | 특정 공연의 러닝타임·가격 등 사실 조회 | O (상세만) |
| `confirm_plan` | 추천안 중 하나를 계획으로 확정·저장 | X (저장은 실행 흐름이 직접) |
| `modify_condition` | 직전 조건 중 일부 변경 ("같은 날 다른 공연") | O |
| `chitchat` | 인사·사용법 | X |

### 2.2 조건 분류
| 구분 | 항목 | 예 |
|---|---|---|
| 기준 조건 | 날짜, 희망 시작 시각(이후) | 토요일, 14:00 이후 |
| 선호 조건 | 지역, 장르 | 대학로, 연극 |
| 제약 조건 | 종료 제한 시각, 예산 상한, 관람연령 | 18:00 전 종료, 5만 원 이하 |

### 2.3 대표 요청 (검증 시나리오 5종 이상)
| # | 요청 | 유형 | 기대 동작 |
|---|---|---|---|
| S1 | "토요일 2시 이후 대학로에서 5만원 이하 연극 보고 6시 전에 끝내고 싶어" | 한 번에 충족 | 목록→상세→판단→시설→주변 검색, 추천 |
| S2 | "일요일 7시 이후 시작해서 9시 전에 끝나는 3만원 이하 뮤지컬" | 재계획 | 1차 후보 전원 미충족 → 장르/지역 확장 재계획 |
| S3 | "평일 오전 10시~11시 사이 끝나는 공연" | 상한 도달 | 재계획 3회 후 중단, 조건 조정 되묻기 |
| S4 | (카카오 키 누락 또는 상세 조회 일부 실패 상태) S1 | Tool 실패 | 실패 사유 기록, 나머지 진행, 안내 |
| S5 | "안녕, 뭐 할 수 있어?" | Tool 불필요 | 계획 단계 생략, 사용법 응답 |
| S6 | "6시 전에 끝나야 해" (시작 기준 없음) | 되묻기 | Tool 호출 전 날짜/시작 시각 질문 |
| S7 | S1 후 "같은 날 뮤지컬로" | 맥락 유지 | 날짜·시각·예산 유지, 장르만 갱신 |

### 2.4 저장 결과물과 겹침 처리
- 핵심 값: 공연 ID, 공연명, 공연장, 날짜, 시작 시각, 종료 시각, 가격, 메모, 생성 일시
- 같은 날짜에 `[시작, 종료)` 구간이 겹치는 계획이 있으면 **저장은 하고** 응답에 `overlaps: [...]`로 알린다.

## 3. 기능 요구사항 표 (도메인 반영)

| 번호 | 분류 | 요구사항명 | 상세 (공연 도메인) | 우선순위 |
|---|---|---|---|---|
| F3001 | Tool | Tool 명세 정의 및 등록 | 레지스트리에 이름·설명·입출력 스키마 등록, 외부 API 툴/로컬 서버 API 툴 구분, 공통 응답 `{ok, data \| error{code,message}}` | 필수 |
| F3002 | Tool | 후보 조회 Tool | KOPIS 공연목록으로 기간·지역·장르별 공연 후보 확보. 날짜 미지정 시 기본값(오늘~+7일) | 필수 |
| F3003 | Tool | 상세정보 조회 Tool | KOPIS 공연상세로 러닝타임·회차·가격·연령 확보. 비어 있으면 `NO_RUNTIME`/`NO_SCHEDULE`/`NO_PRICE` | 필수 |
| F3004 | Tool | 보조 정보 검색 Tool | 카카오 로컬로 공연장 주변 식당·카페·주차장 검색. 결과 없으면 `NO_RESULT` | 필수 |
| F3005 | Agent | 사용자 요청 분석 | 기준/선호/제약 조건 추출, 미추출 값은 null | 필수 |
| F3006 | Agent | 작업 계획 수립 | 의도별 Tool 호출 순서 구성, 불필요 Tool 제외 | 필수 |
| F3007 | Agent | Tool 호출 및 결과 통합 | 목록 ID → 상세 → 시설 좌표 → 주변 검색 연결, 실패 시 사유 기록 후 진행 | 필수 |
| F3008 | Agent | 제약 적합성 판단 | `종료 = 회차 시작 + 러닝타임`, 시간·예산·연령 비교. 회차 정보가 없으면 시각을 지어내지 않고 "늦어도 HH:MM 시작" 역산 제시 | 필수 |
| F3009 | Agent | 재계획 | 충족 후보 0개일 때만, 확보 결과 재사용, 상한 3회 | 필수 |
| F3010 | Agent | 대화 맥락 유지 | 조건 슬롯·추천 요약 보관, 변경 조건만 갱신, Tool 원본 미보관 | 필수 |
| F3011 | Agent | 최종 응답 생성 | 추천 + 주변 장소 + 판단 기준 + 근거 Tool 결과 + 제외 사유 | 필수 |
| F3012 | 로깅 | 실행 이벤트 발행 | 단계 진입/종료, Tool 요청/응답/소요시간, LLM 판단+이유 | 필수 |
| F3013 | 로깅 | 실행 로그 저장 | 구독 → 세션 단위 SQLite 저장, LLM 미사용 | 필수 |
| F3014 | 로깅 | 실행 로그 조회 및 삭제 | 목록·상세·삭제, 수정 API 없음 | 필수 |
| F3015 | 계획 | 계획 저장 및 조회 | 관람 계획 저장, 겹침 알림 | 필수 |
| F3016 | 계획 | 계획 수정 및 삭제 | 날짜·시각·메모 수정, 삭제, 화면 즉시 반영 | 필수 |
| F3017 | 서버 | 백엔드 API 서버 구현 | FastAPI, `/api/chat`, `/api/plans`, `/api/logs` | 필수 |
| F3018 | UI | 프론트엔드 화면 구현 | 바닐라 JS, 대화 화면 + 계획 관리 화면 | 필수 |
| F3019 | UI | 실행 과정 및 상태 표시 | 단계·Tool 이력 타임라인, 재계획 구분, 처리 중/오류/키 누락 안내 | 필수 |
| F3020 | 로깅 | 이상 징후 판단 | 반복 호출·과다 재계획·계획 외 호출 규칙 판정, 이상 시만 LLM 진단 | 심화 (선택) |
| F3021 | Agent | Planner·Worker 구조 전환 | Planner/Worker 분리, Worker는 재시도 가능 실패에서만 LLM | 심화 (선택) |
| F3022 | Tool | RAG 검색 Tool | — | 심화 (미선택) |
| F3023 | Tool | 캘린더 연동 Tool | — | 심화 (미선택) |
