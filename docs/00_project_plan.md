## 3. 하네스 / 에이전틱 엔지니어링 적용 방침

### 3.1 개발 하네스 (Claude Code와 개발하는 방식)
- **스펙 우선**: `docs/` 문서 확정 → 테스트 작성 → 구현 순서. 구현이 문서와 다르면 문서를 먼저 고친다.
- **CLAUDE.md**: 불변 규칙(버전 고정, Tool은 예외를 던지지 않음, 로깅 Agent에 LLM 금지, 키 하드코딩 금지 등) 명시.
- **검증 하네스**: 명세 4장의 확인 항목을 pytest로 옮긴다. 외부 API는 실제 응답을 녹화한 fixture로 대체하여 오프라인·결정적으로 실행.
- **시나리오 러너**: 대표 요청 5종을 재생하고 실행 로그·응답을 기대값과 대조.
- **가드(hooks)**: 커밋/완료 전 키 노출 검사, 테스트 실패 시 완료 차단.
- **역할 분리**: 기능 단위로 구현 → 리뷰(서브에이전트) → 검증 루프.

### 3.2 제품 하네스 (서비스 내부 Agent 구조)
- 결정적인 일(계산, 저장, 판정)은 코드가, 판단이 필요한 일(의도 분류, 조건 추출, 응답 생성, 이상 원인 진단)만 LLM이 담당.
- 모든 LLM 판단은 이유와 함께 이벤트로 남겨 사후 관찰 가능하게 한다.
- 로깅 Agent의 규칙 기반 판정(F3020)이 메인 Agent의 평가 하네스 역할을 한다.
